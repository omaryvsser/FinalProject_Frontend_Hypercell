# Cinema Ticketing Home Page Progress

## Goal

Build the first version of the Cinema Ticketing Platform Home Page using Angular standalone components and Angular Material.

The completed page structure includes:

- A shared navbar
- A Home Page route
- A Discover section
- A responsive Material search interface
- A reusable Material movie card
- A shared footer
- Navigation to the Login and My Tickets pages

## Application Structure

The root application layout is:

```text
Navbar
  ↓
Current routed page
  ↓
Footer
```

The navbar and footer are outside `router-outlet`, so they remain visible when the route changes.

## Routes

File: `src/app/app.routes.ts`

The application currently has these routes:

| URL | Component | Purpose |
| --- | --- | --- |
| `/` | `Discover` | Displays the Home Page |
| `/login` | `Login` | Displays the Login Page |
| `/my-tickets` | `MyTickets` | Displays the customer's tickets page |

`RouterLink` changes the active Angular route without reloading the entire browser page.

`RouterOutlet` provides the location where Angular displays the component for the active route.

## Navbar

Files:

- `src/app/shared/components/navbar/navbar.ts`
- `src/app/shared/components/navbar/navbar.html`

The navbar uses these Angular features:

## Home Page

Component: `Discover`

Files:

- `src/app/features/public/discover/discover.ts`
- `src/app/features/public/discover/discover.html`
- `src/app/features/public/discover/discover.css`

The Home Page currently contains:

- A main heading

The search interface uses:

## Movie Card

Files:

- `src/app/shared/components/movie-card/movie-card.ts`
- `src/app/shared/components/movie-card/movie-card.html`
- `src/app/shared/components/movie-card/movie-card.css`

The movie card uses:

- `MatCardModule`
- `MatButtonModule`
- Angular signal inputs

The reusable signal inputs are:

```ts
readonly title = input.required<string>();
readonly genre = input.required<string>();
readonly showtime = input.required<string>();
readonly cinemaName = input.required<string>();
```

`input.required<string>()` means the parent component must provide a text value.

The card template reads signal values by calling them:

```html
{{ title() }}
```

The Home Page currently provides temporary values like this:

```html
<app-movie-card
  title="Interstellar"
  genre="Science fiction"
  showtime="Friday, 8:00 PM"
  cinemaName="Hypercell Cinema"
></app-movie-card>
```

The card uses the official Angular Material card structure:

- `mat-card`
- `mat-card-header`
- `mat-card-title`
- `mat-card-subtitle`
- `mat-card-content`
- `mat-card-actions`
- A Material action button

Its width is responsive and is limited to 400 pixels so it does not stretch across the entire screen.

A poster image was not added because the project does not currently contain a movie poster asset and the backend response does not provide a poster URL.

```text

    ↓ renders the values

```

## Intentionally Incomplete Features

The following features have not been implemented yet:

- The Search button does not perform a search.
- The search field is not connected to Angular form state.
- Movie listings are not loaded from the backend.
- Interstellar is temporary static data.
- The View Showtimes button does not navigate yet.
- A movie poster is not displayed.
- The Login Page is not implemented.
- Authentication and route protection are not connected.
- Movies and Cinemas navigation pages do not exist yet.
- Final visual and responsive polishing is not complete.

## Backend Note

The inspected backend branch is `feat/security`.

Authentication currently exposes:

```text
POST /api/v1/auth/login
```

The current public listing endpoint is:

```text
GET /api/public/events
```

It supports category, start date, page, and size parameters. It does not currently support searching by movie title. For that reason, the frontend Search button was not connected to a fake or unsupported API request.

The backend still uses older event terminology in several files. The frontend uses cinema terminology for the Cinema Ticketing Platform.
